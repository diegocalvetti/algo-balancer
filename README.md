# 🧮 Algo Balancer — Auction-Arbitrated AMM on Algorand

An experimental AMM protocol built with [AlgoKit](https://github.com/algorandfoundation/algokit-cli), inspired by Balancer's weighted pool model and extended with a novel **auction-based arbitrage mechanism**.

> ⚠️ This project is a technical prototype and not production-ready.

## Contracts

### AssetVault — Managed Weighted Pool
A fully featured multi-asset pool with customisable weights. A designated manager controls fees, weight transitions, token composition, and can pause trading. Fees accumulate passively as invariant growth, increasing LP token value over time. Suitable as a trading pool, a DAO treasury, or a passive index fund when swaps are permanently disabled.

### AssetDex — Auction-Arbitrated Pool (AWP)
Same weighted pool mechanics as AssetVault, with a restructured economic layer. The arbitrage role is sold each epoch through an on-chain first-price auction. MEV is made explicit, predictable, and redirected to liquidity providers before any trading begins.

## Features

- **Weighted liquidity pools** — arbitrary weight distributions (80/20, 60/20/20, etc.)
- **Multi-asset swaps** — constant mean market maker formula with weight-aware pricing
- **LP token minting and burning** — proportional multi-asset and single-asset deposits
- **Gradual weight transitions** — linear interpolation to limit arbitrage exposure during rebalancing
- **Token addition and removal** — proportional weight rescaling preserves existing spot prices
- **Epoch-based arbitrage auction** — open bidding, automatic epoch scheduling, pro-rata LP rewards
- **Dynamic fee control** — arbitrageur sets trader fees within a protocol-enforced cap

## Arbitrage in Standard AMMs

In a standard AMM, the protocol never reacts autonomously to external price movements. When market prices shift, the pool's implied prices become stale — and arbitrageurs step in to restore equilibrium, profiting from the difference.

This process is necessary for price discovery, but costly for liquidity providers. Every arbitrage trade extracts value that would otherwise remain in the pool. Liquidity providers bear this cost silently, with no compensation and no predictability. The broader phenomenon — where external actors capture value generated by the protocol — is known as **MEV (Miner Extractable Value)**.

Existing approaches either try to suppress MEV after the fact (Flashbots), eliminate intra-batch arbitrage through off-chain matching (CoW Protocol), or adjust fees dynamically to reduce LP losses. None of them make the arbitrage role itself explicit.

## A Different Approach — Arbitrage as a Contractual Role

This protocol treats arbitrage not as a side effect, but as a **first-class component of the system**.

Instead of leaving MEV to whoever submits the fastest transaction, the protocol runs a periodic **on-chain auction**. The winner — the **Arbitrageur** — acquires exclusive operating rights for a fixed period called an **epoch**:

- **Fee-free swap execution** — the Arbitrageur can trade without paying fees, making arbitrage profitable even on small price discrepancies
- **Fee rate control** — the Arbitrageur sets the fee rate paid by ordinary traders, optimising it dynamically to maximise epoch revenue
- **Arbitrage surplus** — any profit from correcting price discrepancies belongs entirely to the Arbitrageur

In exchange, the Arbitrageur pays an upfront amount to the pool's liquidity providers at the start of the epoch. This payment is determined by competitive bidding — rational Arbitrageurs bid up to their expected profit, so the auction price converges to the true market value of the MEV opportunity.
```
Epoch timeline:

  [ Auction open ] ──► [ First bid starts countdown ] ──► [ Auction closes ]
                                                                    │
                                                                    ▼
                                              [ Arbitrageur installed, epoch begins ]
                                              [ LP reward distributed immediately   ]
                                              [ Next auction opens in parallel      ]
                                                                    │
                                                                    ▼
                                                        [ Epoch ends, rights expire ]
```

The result is a clean separation of roles:
- **LPs** receive a guaranteed, predictable payment at epoch start — decoupled from trading volume and MEV dynamics
- **Arbitrageurs** compete openly, assuming market risk in exchange for economic control of the pool
- **Traders** interact with a standard AMM interface — same swap formula, same slippage protection, dynamic fees set by the Arbitrageur
